# 앱 화질 재학습 검출기 평가 — 2026-09-19

새 검출기는 공개 test의 앱 화질 이미지에서 기존 모델보다 신호등·횡단보도 검출이 개선됐다. 다만 운영 confidence=0.40에서 작은 신호등의 74%를 여전히 놓친다. 실제 앱 촬영 정답 평가셋은 확인되지 않아 실사용 성능을 확정할 수 없다.

## 평가 범위

- 공개 데이터 test 45장, 신호등 120개(작은 신호등 96개), 횡단보도 121개.
- 두 검출기에 동일한 canvas 960px/JPEG quality=0.8 이미지를 입력. 공개 test이며 실제 앱 촬영 이미지가 아니다.
- 새 색상 분류기 체크포인트는 발견되지 않았다. 두 조합 모두 같은 기존 MobileNetV3-Small 분류기를 사용했다.
- detector confidence=0.40, NMS IoU=0.70, GT matching IoU=0.50, imgsz=960, FP32, batch=1.
- 작은 신호등 정의: 전송 이미지에서 GT bbox 면적 < 32×32px. AP는 별도 confidence=0.001 패스로 계산.
- 분류기 confidence=0.60, padding=0.10, min crop=6px, imgsz=224.
- GPU: NVIDIA GeForce RTX 5080 Laptop GPU. 모델별 warmup 10회, 프레임당 3회, 실행 순서 교대, CUDA 동기화.

## 색상과 누락

빨강→초록과 초록→빨강 오류는 두 조합 모두 0건이다. 이는 검출된 신호등에 대한 결과이며 전체 신호등을 모두 판별했다는 뜻이 아니다.

| 정답 | 기존: 정답 색상 / 미검출 | 새 검출기+기존 분류기: 정답 색상 / 미검출 |
|---|---:|---:|
| 빨강 93개 | 23 / 70 | 35 / 58 |
| 초록 27개 | 8 / 19 | 10 / 17 |

GT 박스를 직접 crop한 기존 분류기는 120/120개를 맞혔다. 이 작은 공개 test에서는 색상 혼동보다 검출 누락이 주된 실패 요인이다. unknown 정답은 없어 unknown 성능은 평가하지 못했다.

JPEG 디코딩·파일 읽기·네트워크·브라우저 압축·UI·횡단보도 후보 연결 시간은 제외했다. 검출된 모든 신호등을 분류하므로 새 모델의 검출 수 증가도 전체 시간 증가에 영향을 준다. 기기/부하에 따라 변동하며 실제 앱 전체 지연과는 다르다.

## 학습 기록과 비교의 한계

- 저장된 실행은 최대 30 epoch, patience=7이다. 26 epoch에 조기 종료됐고 validation mAP50–95 최고값은 19 epoch의 69.516%다. 50 epoch 변경은 적용되지 않았다.
- 기존 검출기는 단계적 추가학습 이력이고 새 검출기는 원본 yolo26s.pt에서 시작했다. 따라서 차이를 이미지 화질 하나의 인과효과로 단정하지 않는다.
- 실제 앱 세션 폴더에서는 모델 출력 results.jsonl과 세션 manifest만 확인됐으며, 정답 LabelMe/annotations는 찾지 못했다. 모델 출력은 정답으로 사용하지 않았다.
- 실제 앱 촬영 정답 이미지/라벨 경로가 필요하다. 새 분류기를 다른 경로에서 학습했다면 해당 체크포인트 경로도 필요하다.
