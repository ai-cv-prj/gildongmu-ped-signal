01 · Executive summary

핵심 결과

93.22%파인튜닝 후 YOLO mAP50
90.31%파인튜닝 후 YOLO recall
100%MobileNet test accuracy · 120장
44.66–58.45전체 영상 측정 FPS 범위

결론. 기본 YOLO의 보행자 신호등 탐지 성능은 낮았지만 단일 클래스 파인튜닝 후 mAP50이 32.93%에서 93.22%로 상승했다. 색상 분류 후보 두 모델은 동일한 정확도를 보였으며, 크기와 속도를 고려해 MobileNetV3-Small을 최종 선택했다.

실제 영상의 red/green 출력 횟수는 정답 라벨과 비교한 정확도가 아니다. 실영상 정량 정확도는 별도의 프레임 라벨링 후 계산해야 한다.

02 · Architecture

모델 역할을 분리한 2단계 구조

1. YOLO 검출

pedestrian_signal신호등의 위치만 단일 클래스로 검출
→

2. Crop

박스 + 10% 여백검출 영역을 분류기 입력으로 변환
→

3. MobileNet

green / red학습된 색상 분류기가 상태 판단
→

4. 최종 출력

red / green / unknown색 confidence 0.70 미만은 unknown 처리
설계 원칙: YOLO에 빨강·초록 클래스를 중복 학습시키지 않고 위치 검출과 색 판단을 분리했다. 각 모델을 독립적으로 평가하고 교체할 수 있으며, 작은 crop에는 경량 분류기를 적용할 수 있다.

05 · YOLO detector

파인튜닝 전후 성능 비교

Precision 모델이 신호등이라고 탐지한 것 중 실제 신호등인 비율. 높을수록 오탐이 적다.
Recall 실제 신호등 중 모델이 찾아낸 비율. 높을수록 놓친 신호등이 적다.
mAP50 예측 박스와 정답 박스가 50% 이상 겹치는 기준에서 계산한 종합 탐지 성능.
mAP50–95 박스 겹침 기준을 50%부터 95%까지 높여가며 평균한 더 엄격한 종합 성능.

5 epoch 시험 학습

`yolo26s.pt`에서 시작해 파이프라인과 메모리 사용을 확인했다. 마지막 epoch가 이 실행의 최고점이었다.

최고 가중치에서 추가 학습

1단계 `best.pt`를 초기 가중치로 25 epoch를 요청했다. 이는 optimizer 상태를 그대로 잇는 resume가 아니라 새 학습 실행이다.

조기 종료

추가 학습 15 epoch에서 최고점을 기록하고 7 epoch 동안 개선되지 않아 22 epoch에서 종료됐다.

최종 선택

`last.pt`가 아니라 추가 학습 실행의 `weights/best.pt`를 추론 가중치로 선택했다.

운영 초기값: validation F1-confidence 곡선의 최고점은 confidence 약 0.378이었다. 실제 영상에서는 YOLO `--conf 0.38`을 첫 기준으로 사용한다.

확인된 실패 사례
YOLO가 검정·노랑 도로 볼라드를 보행자 신호등으로 오탐했다. 첫 시험에서 볼라드 crop의 분류 confidence는 최대 66.24%였다.
완화 설정
같은 구간 실제 빨간 신호등 confidence는 최소 92.98%였다. 분류 임계값을 0.70으로 올려 애매한 crop은 `unknown`으로 보류한다.

표의 Red/Green/Unknown은 모델 출력 횟수다. 영상에 정답 라벨이 없으므로 정확도, precision 또는 recall로 해석할 수 없다. 또한 `unknown`은 안전하다는 뜻이 아니라 판단을 보류했다는 뜻이다.

검증 상태: 신호등 파트 단위 테스트 32개 통과. 분류기 train/validation/test, YOLO validation, 최종 두 모델의 실제 영상 실행을 완료했다.
